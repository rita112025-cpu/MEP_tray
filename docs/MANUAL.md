# 使用手冊（MANUAL）

> 規範值未驗證，不得視為合規；零問題不代表合規。
> 本報告僅涵蓋本工具已實作之檢查項，不等同於完整法規合規審查。
> 安裝見 [INSTALL.md](INSTALL.md)；架構見 [ARCHITECTURE.md](ARCHITECTURE.md)；驗證狀態見 [VERIFICATION.md](VERIFICATION.md)。

## 1. 操作步驟

1. 啟動：`python -m mep_tray.webui`，複製終端機印出的網址（含 token）到瀏覽器。
2. 填尺寸：房間 X／Y／Z（公尺）、橋架寬度與高度（mm）、橋架用途（電力／訊號）、起點與終點座標（公尺）。終點最多 3 個（多終點會產生分支）。
3. 勾規範：至少一套。多套同時勾選時，每個參數取最嚴格的值，並在報告中註明由哪一套決定。
4. 選障礙物檔（可略）：上傳 JSON，格式見第 2 節。
5. 按「執行」。同時只跑一個工作；忙碌時按鈕會回報「已有一個工作在執行」，等它完成再按。工作無法取消。
6. 結果區顯示：狀態、各項發現、下載連結（DXF、DWG、Revit 匯入 JSON、HTML 報告、manifest）。報告用瀏覽器「列印 → 另存 PDF」。

格距（`cell_m`）只能選 0.25、0.2、0.1、0.05 m，預設 0.25。0.05 m 只在網格 ≤ 500,000 格時可選；網格上限 3,000,000 格。座標必須是格距的整數倍，否則回 `misaligned`。格距越小越慢，越容易撞到搜尋上限。

## 2. 障礙物 JSON

檔案內容可以是清單，或 `{"obstacles": [...]}`。範例：

```json
[
  {"name": "冷卻水主管", "kind": "water", "lo": [5.0, 0.0, 1.0], "hi": [5.3, 4.0, 1.3]},
  {"name": "既有風管", "kind": "duct", "lo": [8.0, 2.0, 2.5], "hi": [8.6, 6.0, 3.0]}
]
```

| 欄位 | 規則 |
|---|---|
| `name` | 1～100 字元、不含控制字元；原樣顯示，**不會被改寫**，請勿放含個人路徑或機敏資訊的文字 |
| `kind` | `water`、`duct`、`heat`、`structure`、`tray_power`、`tray_signal`、`other` |
| `lo`、`hi` | 各為 3 個有限數字（公尺，與房間同一座標系）；每軸 `lo < hi` |
| 數量 | 最多 200 個 |
| 大小 | 檔案 256 KB 以內 |

檔案有問題時介面會顯示紅字並**不送出**，要更正或移除檔案才能執行。

## 3. 座標與單位

- 原點為你輸入的座標系原點；工具不假設它對應 Revit 專案基準點、測量點或 Shared Coordinates（Shared Coordinates 不支援）。
- 介面與 `obstacles` 用公尺；DXF 與匯入 JSON 用 mm；Revit 匯入腳本內再換算成英呎。
- Revit 座標基準欄位預設「未指定」（UNSPECIFIED），不會被猜成任何一種。

## 規範表（5 套）

目前內建 5 套（`rules.json` 的 `codes`）。全部 `verified: false`。

| 代號 | 名稱 | 出處欄摘要 | verified |
|---|---|---|---|
| `CNS` | CNS 國家標準（電纜架／電氣裝置） | 設計預設值，無權威出處 | false |
| `IEC` | IEC 61537／60364／61918 | 設計預設值，無權威出處 | false |
| `NEC` | NEC（NFPA 70）Article 392 | 設計預設值，無權威出處 | false |
| `TW_BUILDING` | 建築技術規則（建築設備編） | 設計預設值，無權威出處 | false |
| `MRT_APPX_C` | 業主需求書附錄C（捷運管線佈設，汐東捷運） | 由技能 PDF 文字抽取；附件A矩陣個別格值須回查原檔 | false |

第 5 套 `MRT_APPX_C` 是使用者指定的專案特定規範；數值來自文字抽取，附件A矩陣的個別格值有抽取錯位的風險，`rules.json` 的 `source` 欄已註明須回查原檔。

## 4. 錯誤代碼

與介面 `mep_tray/webui.py` 的 `HUMAN` 表一致（階段／代碼 → 說明）：

| 階段／代碼 | 意義 | 處理 |
|---|---|---|
| route／`no_route` | 找不到可行路徑 | 移動障礙物，或確認起訖點間有空間 |
| route／`misaligned` | 起訖座標未對齊格距 | 改成格距的整數倍 |
| route／`search_limit` | 搜尋範圍太大 | 放大格距或縮小房間 |
| route／`grid_too_large` | 該格距下房間太大 | 放大格距或縮小房間 |
| route／`obstacle_work_limit` | 障礙物範圍過大或過多 | 縮小障礙物、減少數量或放大格距 |
| route／`endpoint_blocked` | 起點或終點落在障礙物淨距內 | 移動起訖點或障礙物 |
| validate／`invalid_input` | 欄位不合法 | 檢查數值與範圍 |
| validate／`no_codes` | 沒有勾規範 | 至少勾一項 |
| rules／`invalid_rules` | 規範設定有問題 | 檢查 `rules.json` 與代號 |
| output／`run_exists` | 版本編號衝突 | 再按一次 |
| io／`os_error` | 寫入輸出失敗 | 檢查磁碟空間與權限 |

另有 HTTP 層錯誤：400（欄位或 JSON 不合法，附欄位名）、403（Host／Origin／跨站檢查失敗）、409 `busy`（已有工作）、413（本文超過 1 MB）、417（不支援 Expect）、503（連線過多）。

## 5. 怎麼讀報告

1. **頂端橫幅**：固定文字「規範值未驗證，不得視為合規；零問題不代表合規。」只要任一勾選的規範值是 `verified: false` 就會出現。
2. **範圍說明**：「本報告僅涵蓋本工具已實作之檢查項，不等同於完整法規合規審查。」永遠出現，包含全部規範值都已驗證時。
3. **三種狀態**：通過（PASS）、不符（FAIL）、未驗證（UNVERIFIED）；碰撞另標 CLASH。「通過」只表示比對了一個**尚未驗證**的數值。
4. **發現清單**：每筆列出位置、規範依據、修正建議。總數先於表格；超過上限（500 筆）的部分被截斷，並標明截斷。
5. **Revit 狀態**：報告固定寫「未於 Revit 驗證」等字樣，不隨你本機測試結果改變。

## 6. 版本與比對

- 每次成功執行建立一個不可變的 `output/<run_id>/`，內含 `manifest.json`（輸入、規則快照、結果的 sha256）。舊版本全部保留。
- 比對網址：`/t/<token>/diff/<舊run_id>/<新run_id>`。報告即時產生，不存檔。
- 差異來源（`source`）：`inputs`（只有輸入不同）、`rules`（只有生效規則不同）、`both`、`none`（輸入、規則、結果都相同）；輸入與生效規則都相同、結果卻不同時，引擎指紋不同記為 `engine`，相同記為 `unexplained`（需人工調查）。另有獨立的 `engine_changed`，為真時報告會附「引擎版本亦不同，差異可能包含引擎變動」。
- 發現以（種類、對象、規範）彙總計數，不做位置配對：同一對象的位置移動不會顯示為差異。
- 完整性檢查只能偵測損壞，無法防止有意竄改（任何能改 manifest 的人也能改雜湊）。
- 不確定性：DWG 內容不保證逐位元相同；HTML 報告與 DXF 受執行環境影響；`created_at` 不納入結果雜湊。

## 7. 規範值怎麼改成「已驗證」

1. 技術人員對照現行條文，確認 `rules.json` 中**單一規範**每個數值。
2. 在該規範填入條文出處（`clause`、`source`），再把該規範的 `verified` 改為 `true`。一次只改一套，不要整檔批次改。
3. 重新執行；之後的版本比對會顯示規則變更與 `verified` 的變化。
4. 全部勾選的規範都 `verified: true` 時，橫幅不再出現，但範圍說明仍在。

## 8. 限制（務必閱讀）

1. **所有規範值皆為未驗證的設計預設值**，無法視為任何法規的合規結論；第 5 套 `MRT_APPX_C` 的數值來自文字抽取，附件A矩陣個別格值須回查原檔。
2. **Revit**：只在 Revit 2025.5 驗證過建立與提交（直線、彎頭、三通、四通）與儲存重開（人工確認）。尺寸、端點座標、Comments 的讀回，以及專案基準點、union、其他回滾路徑，都是未驗證，見 [VERIFICATION.md](VERIFICATION.md)。Revit 2027 相容性未驗證。交付是**系統族建模匯入器，不是 .rfa**。
3. **AutoCAD**：只在本機以 AutoCAD 2027 的 `accoreconsole.exe` 驗證（稽核 0 錯誤、DWG 為 AC1032）。其他版本與機器未驗證。
4. **網頁介面**只在內建瀏覽器驗證。真實按 Enter 送出、視覺外觀、其他瀏覽器、螢幕閱讀器為 **HUMAN TEST PENDING**。自行驗證：(a) 在 Chrome／Edge 開網址；(b) 在最後一個欄位按 Enter，確認會執行一次；(c) 只用 Tab 走完全部欄位，確認每個都有可讀的名稱；(d) 螢幕閱讀器朗讀錯誤訊息。
5. 符號連結的下載防護測試在這台機器 **被略過（未驗證）**。
6. 效能（實測）：格距 0.25 m 的一般案例數秒；0.1 m 的小場景約 5 秒；障礙物預算上限（300 萬單位）最壞約 6 秒；30 個障礙物的實際規模場景只用掉預算的 4.8%（0.25 m）。
7. DXF 內的時間戳記是固定常數，不是真實建立時間；DWG 不具決定性。
8. 發現以彙總比對、不配對位置；`code_sha256` 偏向多報引擎變動。
9. 在 POSIX 上，發布步驟的 rename 可能覆寫同名空資料夾；暫存清除失敗不阻擋重跑同一 run_id。
10. 使用者輸入的文字（障礙物名稱等）不被改寫，請避免放機敏路徑。
11. 工作無法取消；token 出現在網址路徑中（不要把網址貼到公開處）；前端需要 JavaScript。
